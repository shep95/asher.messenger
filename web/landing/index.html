How it works

Encryption never needed the internet. Delivery did.

Signal Protocol runs entirely on the device. What a server did was hand out prekeys, assign identities and hold messages for people who were offline. Asher moves those three jobs onto people and radios and leaves the cryptography exactly where it was.

The same encryption

Every message is Signal Protocol ciphertext: PQXDH to start a session and the Double Ratchet after that, with a post-quantum Kyber-1024 prekey. Asher calls the same libsignal code the apps already use. Nothing about the encryption changes when the link does.

Identity is your device key

No phone number. Your address is a fingerprint: sixteen bytes of SHA-256 over your Signal identity key, shown as thirty-two hex characters. Nobody assigns it and nobody can revoke it. It names a device, not a person.

Contact cards instead of a server

Your prekey bundle travels with you as a signed contact card: a QR code you show someone, or a beacon you broadcast over the radio. Both signatures are checked before the card reaches the protocol code. The trade-off, stated plainly: there are no one-time prekeys, as with Signal's last-resort Kyber prekey.

Store, carry, forward

Every node that sees a message carries it until it is acknowledged or expires, and hands it to each new neighbour it meets. Relays cannot read what they carry. Bundles are at most 4 kB and fragment to fit LoRa frames, so the same code runs over Bluetooth LE, LoRa radios (RNode, KISS), serial cables, a LAN, or a gateway with a satellite modem.

Security

What was checked, and what was fixed.

On 30 September 2026 every vendored component and this repository's own additions went through a security audit. This is what it did, not a promise about what remains.

The audit

  • Automated scanning of dependencies, secrets and configuration: cargo audit, pnpm audit, Trivy, gitleaks, and the GitHub Advisory Database matched against the Maven dependency trees.
  • Manual review of the authentication, authorization, transport-security, IPC, file-handling, attestation and remote-control surfaces of each client, service and library.
  • Dependency patches in ringrtc, SVR2, the registration service (38 advisories, one deferred) and the chat server's Jetty.
  • Code fixes, each with a file and line: internal-only server paths that the websocket bypassed; a registration service with no caller authentication; a Desktop file:// handler that exposed the database key and IPC channels with no sender check; an iOS device-transfer path traversal and an internal build flag left on for release; Android domain fronting on by default for brand builds; and a brand-override bug that skipped key-transparency signature checks.
  • Verification stated per change. Rust, Go, JDK and TypeScript changes were compiled and tested here; Android and iOS changes were verified by inspection only, because no SDK was available.
  • An inventory of every party that can influence or observe a deployment (compiled trust anchors, remote configuration, push services, DNS fallbacks, third-party SDKs), each removed for brand builds, made operator-controlled, or listed with the reason it stays. Nothing resembling a covert access mechanism was found, and the audit does not claim more than that.

Mesh threat model

  • Relays hold no keys. A node that forwards a bundle never holds key material for it; a test asserts the relay emits no plaintext and drops the bundle once the acknowledgement arrives.
  • Cards and beacons are authenticated. Both signatures on a contact card are checked on decode, and a beacon is rejected unless the card's fingerprint matches its source. Acknowledgements are bare bundle ids; only the original sender turns one into "delivered".
  • Stores are bounded. Duplicates are dropped by id, every bundle has a TTL (7 days by default), the carry store has a byte budget (8 MiB) with nearest-expiry eviction, and link queues are capped at 256 frames.
  • Fragments are limited. Fixed-width fields and 16-bit length prefixes, no allocation on garbage input beyond the declared length, 4 kB per bundle, 7 hops, and a 120 s reassembly timeout.
  • No code download. The transport ships inside the normal libsignal build, behind a feature flag that is off by default. Radios are hardware you pair, not software you install.
  • Still visible on the air: source and destination fingerprints, which relays need for routing. Content is not. No radio hardware was available in the audit environment; the protocol above the byte pipe is what is tested.

Offline

Three words for how you are connected.

The pill under a conversation's name is the one place the transport shows itself. Everything else looks the same on any link.

Orbit

The internet is reachable. Messages go through the server as they always have.

Mesh · 2 hops

A peer is reachable over radio, directly or through nodes in between that cannot read the traffic.

Carrying

Nobody is in range yet. The message is stored and will be handed to the next node that appears.

Out of range

Nothing. You can still write; it will carry when a link comes back.

For organisations

One stack. Your name on it.

Asher is one brand of a platform that white-labels the whole Signal stack: the three clients, the chat server, its satellite services and the shared libsignal library. A brand is a JSON profile (name, bundle ids, domains, server keys, root CA) that one script renders into every platform, and every brand runs against its own servers. Nothing here connects to Signal's infrastructure, and nothing may.
